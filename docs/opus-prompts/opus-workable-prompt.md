## 0. What you are building

A web platform with three connected modes and one shared account, credit wallet, and library:

1. **Forge (PartForge-style parametric CAD).** The user describes a mechanical or household part in plain language. An AI agent writes it as parametric JavaScript code that builds real geometry. The platform runs that code and gives the user a "forge": a self-contained interactive page with a 3D viewer, parameter sliders, print checks, and export buttons (STL, 3MF, STEP). Parameters can be changed live, and the model regenerates.
2. **Generate (Meshy-style AI 3D).** The user types a prompt or uploads images, and a third-party AI model returns a mesh. Two steps: a cheap **preview** (shape only), then a **refine** (textured) that references the preview. Also retexture and remesh.
3. **Print.** Any model from Forge or Generate can be sent to print. Two ways to order:
   - **Upload and quote:** the buyer uploads an STL/3MF/OBJ, gets an automatic quote, and orders. Quote works without an account; the account is required at checkout.
   - **Listing order:** a creator enables printing on a public model. Buyers see "Order print" on that model page, pick a material, and the order is routed to a print partner.

Build this as a workable product, not a catalogue of everything. Section 9 lists what is deliberately out of scope for the first release.

## 1. Non-negotiable rules

1. **Original brand and code.** Pick your own name, logo, palette, and copy. Do not copy any other product's name, logo, screenshots, copy, layout, or code. PartForge is MIT-licensed and may be used as a dependency with its license and copyright notice preserved. Record that in `LICENSE-AUDIT.md`. Do not copy its source into the repo beyond what the dependency provides.
2. **Official APIs and documented behavior only.** Do not scrape or reverse-engineer third-party sites or apps. Before writing an adapter, read that provider's current official documentation and cite the URL and retrieval date in the adapter's header comment. Never invent endpoints, fields, or signatures. If something is unclear, write it to `docs/decisions.md` as an open question and use a mock.
3. **AI-written code runs in a sandbox.** Forge code generated by the AI is untrusted. It runs only in a Web Worker or an `iframe` with `sandbox` and a strict Content-Security-Policy that blocks network access. It never runs in the main page context. Limit build time and memory. Reject code that imports anything outside the allowlist.
4. **Money is server-authoritative.** Prices, credits, tax, shipping, and refunds are computed on the server. Every money-moving action is idempotent and audited. The client never supplies an amount the server trusts.
5. **Do not stop to ask.** For each ambiguity, pick the most defensible option, record it in `docs/decisions.md` with the alternatives you rejected, and continue. Stop only for a missing secret, and build the mock path first.

## 3. Forge (PartForge-style) — the core feature

### 3.1 The forge contract
Every forge is a Vite app built from one model file. Use this shape, which matches the `partforge` package's documented API (confirm the exact signatures against the installed package's README and types before writing code):

```js
// model.js — the only file the AI writes
export const schema = {
  width:  { type: 'number', default: 40, min: 10, max: 120, step: 1, unit: 'mm', label: 'Width' },
  height: { type: 'number', default: 20, min: 5,  max: 80,  step: 1, unit: 'mm' },
  wall:   { type: 'number', default: 2,  min: 0.8, max: 6, step: 0.1, unit: 'mm' },
  // ...
};

export function build(p, kernel) {
  // use the kernel's primitives; return one or more named parts
  return { body: /* geometry */ };
}

export const verify = {
  profile: 'fdm-0.4mm-nozzle',              // DFM profile, configured in forge-kit
  assertions: [ /* e.g. minimum wall thickness, fits bed 220×220×250 */ ],
};
```

Rules:
- The model file imports only from the allowlist: `partforge` and its subpaths, and nothing else. Enforce with a static check (ESLint rule or AST walk) before the forge builds.
- Parameters are validated against the schema server-side and client-side. Out-of-range values are clamped and the UI says so.
- Each forge has a stable ID and a version. Editing the code creates a new version. Old versions stay accessible.

### 3.2 How a forge is made (agent loop)
1. The user types a prompt, for example "a 40 mm cable clip for a 6 mm cable, with a snap closure."
2. `forge-kit` sends the prompt to the **author** (`FORGE_AUTHOR`). The author gets: the forge contract, three example forges from `packages/forge-kit/examples/`, the parameter schema rules, and the DFM profile. It returns one `model.js`.
3. The code is statically checked, then built in a worker with a timeout of 20 s. It must produce a manifold mesh and pass `verify` assertions.
4. If the build or `verify` fails, the error text goes back to the author for **one** repair attempt. A second failure ends the job with `FORGE_BUILD_FAILED` and shows the error to the user. Credits for the failed attempt are released.
5. On success, the forge is saved as an asset (kind `FORGE`), with its code, default parameters, and a thumbnail rendered in the worker.

**The author is a provider adapter.** Use the same `ModelProvider` pattern as Generate, but with a `FormAuthor` interface: `author(prompt, context) → { code }`. Build `MockAuthor` first. Add one live LLM adapter only after you have read that provider's current documentation and written the chosen rules to an ADR.

### 3.3 The forge page
Each forge opens as a page with:
- **Viewer** (three.js, lazy-loaded): orbit, pan, zoom, `F` to frame, wireframe toggle, bounding-box readout in mm, and a grid at true scale.
- **Parameter panel:** one control per schema entry (number slider with a typed input, boolean toggle, enum select). Changes regenerate the preview mesh in the worker, debounced at 250 ms. Show a spinner during rebuild and keep the last good mesh visible.
- **Checks panel:** the `verify` results as pass/warn/fail rows with plain-language messages ("Wall is 0.8 mm; the printer minimum is 1.2 mm"). A failing check does not block export, but blocks "Send to print" until it is acknowledged.
- **Exports:** STL (fast, Manifold), 3MF (Manifold), STEP (Replicad, exact). STEP export runs on the server worker, not the browser, to keep the page light. Export files expire from storage after 7 days.
- **Send to print:** passes the export to the Print flow as a `PrintPart` with the forge version ID attached.
- **Forks:** "Edit code" opens the model file in a read-only viewer for the MVP. Forking creates a new forge owned by the user with the same code.

### 3.4 Bundled starter forges (ship at least these, written by you, MIT-compatible)
1. Cable clip (parametric width, cable diameter, wall).
2. Rectangular box with lid (wall, inner dimensions, corner radius, and a snap-fit lid).
3. Planter (diameter, height, drainage holes, taper).
4. Filleted box (uses the fillet feature, so it covers the Manifold path).

Each is also a test fixture for `verify` and export.

## 4. Generate (Meshy-style)

### 4.1 Provider contract
```ts
export interface ModelProvider {
  readonly key: string;
  capabilities(modelCode: string): { textTo3D: boolean; imageTo3D: boolean; refine: boolean; retexture: boolean; remesh: boolean; webhooks: boolean; outputs: Array<'glb'|'obj'|'fbx'|'usdz'|'stl'> };
  createTask(input: ProviderInput, ctx: { idempotencyKey: string }): Promise<{ providerTaskId: string }>;
  getTask(providerTaskId: string): Promise<NormalizedTask>;   // QUEUED | RUNNING | SUCCEEDED | FAILED | CANCELED, progress 0–100
  cancelTask(providerTaskId: string): Promise<void>;
  parseWebhook(headers: Headers, rawBody: Buffer): { eventKey: string; task: NormalizedTask } | null;
  verifyWebhook(headers: Headers, rawBody: Buffer): boolean;
}
```

Build `MockProvider` first. It is deterministic, returns one of several bundled test meshes generated by the mesh service, simulates 8–25 s latency, and can replay webhook events out of order and duplicated. Test every webhook path against it.

### 4.2 Live adapter: how to choose and what to record
Pick one provider with a documented public API. Read its current docs and record in ADR-006:
- Create-task and get-task endpoints, and the two-step preview → refine flow if it has one.
- Webhook registration, limits, retry rules, and whether deliveries can repeat or arrive out of order.
- How webhooks are verified. If the docs do not say, do not trust the webhook body. Fetch the task with GET before changing state.
- Credit costs per operation and per model version, and how failed tasks are billed.

If you cannot confirm these from the docs, leave the live adapter as a stub that throws `NOT_IMPLEMENTED`, and say so in the final report.

### 4.3 Flow
- **Text to 3D, preview:** validate prompt (1–600 chars), moderate, reserve credits, create job, poll or receive webhook, download results, store as asset version, run `mesh` analysis.
- **Refine:** creates a child job that references a succeeded preview. Refine is disabled until the preview succeeds.
- **Image to 3D:** upload (quarantine → scan → move), optional background removal, provider task.
- **Retexture and remesh:** input must be an asset version the user owns. Remesh runs in the `mesh` service.
- **Failed jobs are never charged.** Canceled jobs are refunded.

### 4.4 Printability on every mesh
Run `mesh /analyze` on every asset version: watertight, manifold, degenerate faces, flipped normals, units guess, bounding box, and a plain "printable at current scale" yes or no. Offer "Repair for printing," which creates a new version. Never overwrite the original.

## 5. Print

### 5.1 Upload and quote (anonymous allowed)
1. Upload STL, OBJ, or 3MF, up to 150 MB, or send a forge export or a generated asset to print. Anonymous uploads are kept 24 h.
2. Validation: parse → repair if needed → analyze. Show a report and an overhang overlay in the viewer. Offer auto-repair with a before/after comparison.
3. Configure: material (PLA, PETG, ASA to start), color, layer height (0.12, 0.20, 0.28 mm), infill (10–100%), supports (auto or none), orientation (as uploaded or auto), scale (%, with mm readout), and quantity (1–500).
4. Quote: updates 300 ms after the last change. It uses the slicer's real print time and filament mass when `SLICER_MODE=real`. With `estimate`, show "ESTIMATE" and do not allow ordering. The quote shows line items, shipping, tax estimate, total, lead time, and a 30-minute expiry.
5. Sign-in is required at checkout only. Anonymous parts and quotes are claimed on login.

### 5.2 Pricing (`packages/pricing`, pure functions, run in the browser for estimates and on the server for the authoritative price)
```
material_g    = (filament_g + support_g * 0.5) * 1.08
unit_cost     = material_g * cost_per_g[material] + (print_time_h * machine_rate_per_h) + finish_cost
unit_price    = max(min_unit_price, unit_cost * (1 + margin))            // margin set in config
discounted    = round_half_up(unit_price * (1 - quantity_discount(qty)))  // tiers in config
total         = sum(discounted * qty + setup_fee) + shipping + tax − promo
```
- Config lives in `packages/pricing/config/v1.json`. Changing it bumps `pricing_version`.
- Golden fixtures for 10 reference parts are committed JSON. Engine changes must update fixtures in the same change.
- Tests: part too big for the build volume → error with a suggested scale; scale outside 1–1000%; quantity outside 1–500; mixed currency → reject; quote changed more than 2% when repriced → `409 QUOTE_CHANGED`.

### 5.3 Listing orders (second release)
- Creators enable printing on a public asset and set a price per material. Moderation approves the listing before it goes live.
- The platform keeps a platform fee and pays the creator a share, only once the order is delivered and the problem window (14 days) has passed. Until a payout provider is integrated, accrue the balance as pending and show it, but do not pay out.

### 5.4 Partner routing
`PrintPartner` interface: `listCapacity`, `submitItem`, `getItemStatus`, `cancelItem`, `parseWebhook`, `verifyWebhook`. Ship `MockPartner` only. Route to a printer that supports the material, fits the part, and has the shortest queue. Show the partner's city, not internal IDs. Do not claim a real partner exists.

### 5.5 Checkout
- Stripe Checkout (test mode, or mock). The order becomes `PAID` only when the webhook confirms the session completed **and** the amount and currency equal the quote's total.
- Webhooks: verify the signature on the raw body, store the raw event, process once in a transaction, and ignore duplicates.
- Tax: use Stripe Tax if enabled. Otherwise show "tax calculated where applicable" and record the gap in `docs/decisions.md`.

## 6. Money and credits

- Credits are integers. Money is integer minor units. No floats anywhere.
- **Reserve** the maximum cost of a job in one transaction that locks the wallet row. **Commit** the actual cost on success. **Release** on failure, cancel, or expiry. A reaper releases reservations older than job timeout + 1 h.
- Wallet invariants enforced in the database: `reserved >= 0`, `balance >= reserved`. The ledger is append-only (a trigger rejects UPDATE and DELETE). Balance must equal the sum of ledger deltas.
- Property test (fast-check): across random sequences of reserve, commit, release, grant, and expiry, the wallet never goes negative and the balance always equals the ledger sum. 10,000 iterations in CI.
- Plans are seed data, not code. Starting values (adjust in config): Free 100 credits/month; Creator 2,000/month; Studio 10,000/month. Monthly credits expire at period end. Purchased credit packs never expire. Write this in the Billing page and Terms.
- Stripe webhook events handled: `checkout.session.completed`, `checkout.session.expired`, `invoice.paid` (grant idempotent on invoice ID), `invoice.payment_failed`, `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`.
- Refunds: admin-initiated, with a reason, an idempotency key, and a second approval above a threshold set in config.

## 10. State machines (pure transition tables with exhaustive tests; every transition writes an event row)

**Job:** `QUEUED → RUNNING → SUCCEEDED | RETRYING | FAILED | CANCELED`; `RETRYING → QUEUED | FAILED`; `QUEUED → CANCELED`. Success commits credits. Failure and cancel release them, in the same transaction as the status change.

**Forge build:** `DRAFT → AUTHORING → STATIC_CHECK → BUILDING → VERIFYING → READY`; any failure after one repair attempt → `FAILED` with the error.

**Order:** `DRAFT → AWAITING_PAYMENT → PAID → IN_PRODUCTION → SHIPPED → DELIVERED`; `AWAITING_PAYMENT → EXPIRED | CANCELED`; `PAID → CANCELED` (buyer within 1 h, before routing, auto refund); `IN_PRODUCTION → ON_HOLD → IN_PRODUCTION`; any paid state → `REFUNDING → REFUNDED | PARTIALLY_REFUNDED`.

**Order item:** `QUEUED_FOR_PRINT → ROUTED → PRINTING → QC → PASSED → SHIPPED`; `QC → REWORK` (auto reprint, max 2) → `ROUTED`; third failure → `ESCALATED`.

**Reservation:** `RESERVED → COMMITTED | RELEASED | EXPIRED`.

## 12. Security checklist (each item has a test)

- **Forge sandbox:** code runs only in a Worker or sandboxed iframe, with no network, a build timeout of 20 s, a memory cap, and an import allowlist. A test attempts `fetch`, `import` of an unlisted module, and an infinite loop, and each must fail safely.
- **Uploads:** extension and MIME allowlist, magic-byte check, size limits (150 MB print, 20 MB images), zip-bomb limits for 3MF (500 MB uncompressed, 5,000 entries), triangle cap of 25M. Files stay in quarantine until the scan passes.
- **Files:** signed URLs only (5 min download, 15 min upload). Private assets return `404` to non-owners.
- **IDOR tests:** user A cannot read or change user B's forge, asset, job, quote, cart, order, key, or webhook.
- **Money:** server recomputes prices. Stripe amount and currency checked against the quote before the order becomes `PAID`. Idempotency keys on every Stripe call.
- **Webhooks:** raw-body signature check (or GET fetch-back if the provider's signature method is unconfirmed). Dedupe on event key. State only moves forward; a late in-progress event never overwrites a final state.
- **Auth:** magic link is single-use and expires in 15 min. Sessions rotate on login. Admin accounts require TOTP.
- **Headers and logs:** strict CSP with nonces, HSTS, `Permissions-Policy` off for camera and mic. Logs redact auth headers, cookies, signatures, and API keys.
